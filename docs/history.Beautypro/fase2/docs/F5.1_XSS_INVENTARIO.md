## 5. Residual classificado

### 5.1 P1 — mesmo padrão F4.2 (attrs `data-*` com id sem escape) [C]

| Local | Código | Risco | Notas |
|-------|--------|-------|--------|
| `ui/ui-render-clientes-caixa-equipa.js` ~L491 | `data-prof-id="${p.id}"` | Quebra de atributo / markup se `id` contiver aspas | **Candidato F5.2** — simétrico a `data-id` do menu que **já** usa `escHtml(p.id)` |
| `ui/ui-render-clientes-caixa-equipa.js` ~L545 | `data-servico-id="${s.id}"` | Idem | **Candidato F5.2** — menu ao lado já usa `escHtml(s.id)` |

IDs UUID normais = risco prático baixo; inconsistência com o padrão F4.2 = dívida clara.

### 5.2 P2 — baixo / controlado [C]

| Local | Motivo |
|-------|--------|
| `data-tipo="${m.tipo}"` | Enum interno (venda/despesa…), não texto livre de cliente |
| `data-preco="${s.precoBase}"` | Numérico |
| `data-idx="${idx}"` | Índice de array |
| `ia` sugestões `c.label` / `c.pergunta` | Catálogo **estático** em código (`add(score, label, pergunta, tone)`); só `&quot;` em `data-pergunta` |
| Insights `ins.texto` | HTML interno da app; nomes dinâmicos já com `escHtml` no `pushIns` (FIX2) |
| `fatTrendEl.innerHTML` | Só número + seta + CSS var |
| Empty states estáticos em features | Strings fixas |
| SVG / botões icon | Markup fixo |
| `media` `src` | Pipeline safe URL prévia [C histórico] |
